# 杭州麻将助手设计说明

## 1. 目标

构建一个以手机竖屏为主要使用场景的杭州麻将网页助手。单个操作者在开场时将四名玩家映射到真实麻将桌的四个座位，之后通过同一张桌面仪表盘持续查看座位、庄家、老庄状态和累计分数。

产品解决三个问题：

1. 根据真实座位、当前庄家和两颗骰子的点数，引导玩家确定开门位置、数墩方向和发牌顺序。
2. 根据胡牌者、胡牌方式、庄闲关系、老庄状态与三摊承包，计算每名玩家的本局收支。
3. 在确认结算时同步更新累计分、庄家和连庄状态，并保留可撤销的牌局历史。

本期不记录逐张出牌，不分析听牌或牌效率，不提供联网对战、账户或云同步。

## 2. 规则口径

### 2.1 基础规则

- 固定四名玩家，使用 136 张牌。
- 白板为固定财神，不翻财神。
- 默认只处理自摸结算。
- 杠牌不单独计分，只按照最终胡牌方式计分。
- 三摊承包是开场设置项，默认开启，整场牌局中保持不变。
- 闲家胡牌后，由胡牌者接庄。
- 庄家胡牌则继续坐庄。
- 流局时无人得失分，庄家不变，连庄次数也不变。

### 2.2 平庄与老庄

内部用“同一玩家连续坐庄的局数”记录庄家状态，界面使用牌桌习惯称呼：

| 连续坐庄局数 | 界面称呼 | 庄闲倍率 |
| --- | --- | --- |
| 1 | 平庄 | ×2 |
| 2 | 一老 | ×4 |
| 3 及以上 | 二老 | ×8，封顶 |

例：上一局 A 是庄家，本局闲家 B 胡牌，则下一局 B 为平庄 ×2。B 在该局胡牌后继续坐庄，下一局为一老 ×4。B 再次胡牌后继续坐庄，下一局为二老 ×8。

### 2.3 胡牌方式

结算时只选择一个最终胡牌方式，复合牌型使用最终名称，不重复叠乘组成部分。

| 胡牌方式 | 牌型倍率 |
| --- | --- |
| 平胡 | ×1 |
| 七对、爆头、杠开 | ×2 |
| 豪华七对、财飘、杠爆 | ×4 |
| 双豪华七对、杠飘、飘杠 | ×8 |
| 三豪华七对、双财飘 | ×16 |

### 2.4 计分公式

每位输家的支付额为：

`底分 × 胡牌方式倍率 × 庄闲关系倍率`

- 胡家与该输家之间有一方是庄家时，庄闲关系倍率使用当前的 ×2、×4 或 ×8。
- 胡家与输家都是闲家时，庄闲关系倍率为 ×1。
- 胡家所得等于三位输家的支付总和，确保整场四人净分之和始终为 0。

若开启并触发三摊承包，系统先按正常规则计算三家应付总额，再将全部应付金额转由承包者一人支付，另外两名输家支付 0。承包者不能是胡家。

示例：底分 1，当前为一老 ×4，闲家平胡时，庄家付 4，另外两名闲家各付 1，胡家共得 6。若此局触发承包，承包者一人付 6。

## 3. 座位模型

四名玩家永久绑定真实桌面的上、右、下、左四个物理座位。累计分数绑定玩家，不随庄家改变。

庄家是座位上的动态状态，不是固定方位。界面主要使用“庄家、下家、对家、上家”，不在主界面强调东南西北。传统风位仅在发牌规则说明中作为补充解释。

产品由一个人操作，因此所有文字统一朝向操作者，不做四边文字旋转。

## 4. 用户流程

### 4.1 开场设置

1. 在圆角方桌的上、右、下、左四边输入四名玩家姓名。
2. 选择首局庄家。
3. 设置正数底分，默认 1。
4. 设置三摊承包开关，默认开启。
5. 确认开场。四人初始累计分均为 0，庄家状态为平庄 ×2。

姓名不能为空或重复。底分必须为正数。验证通过前不能开始牌局。

### 4.2 桌面仪表盘

主界面始终显示：

- 第几局；
- 当前庄家；
- 平庄、一老或二老及对应倍率；
- 四名玩家在真实座位上的姓名与累计分；
- 两个主要操作：“发牌向导”和“结束本局”；
- 历史记录与新开一场入口。

庄家变化时只移动“庄”标记，不移动玩家卡片。

### 4.3 发牌向导

采用单次掷两颗骰子、总点数开门的方式：

1. 庄家掷两颗骰子，操作者分别输入点数，系统计算总点数。
2. 从庄家算第 1 位，沿行牌方向数总点数，落到哪位玩家，就从其面前的牌墙开门。
3. 在该牌墙从右向左数过与总点数相同数量的牌墩，从下一墩开始取牌。
4. 庄家先取两墩共 4 张，随后按庄家、下家、对家、上家的顺序取牌。每人取 4 张，重复三轮，各有 12 张。
5. 最后一轮庄家跳牌取 2 张，其他三家依次各取 1 张，最终庄家 14 张、闲家各 13 张。

向导在真实座位方桌上高亮当前庄家、开门牌墙、牌墙右端、数墩数量与四人拿牌顺序，而不是只显示文字答案。

### 4.4 本局结算

点击“结束本局”后，从页面底部展开局部向导：

1. 选择“有人胡”或“流局”。
2. 有人胡时选择胡牌者。
3. 选择一个最终胡牌方式。
4. 三摊承包已开启时，选择本局是否触发承包；触发时选择承包者。
5. 查看四人收支预览以及逐项算式。
6. 点击“确认结算并开下一局”。

确认是一个原子操作，同时写入四人累计分、牌局历史和下一局庄家状态：

- 闲家胡牌：胡家接庄，状态重置为平庄 ×2。
- 庄家胡牌：庄家不变，连续坐庄局数加一，依次进入一老 ×4、二老 ×8，之后封顶。
- 流局：四人分数、庄家和连续坐庄局数全部不变。

缺少胡家或牌型、承包者等必要信息时，确认按钮不可用，并给出具体补充提示。

### 4.5 历史与撤销

每局历史记录以下内容：

- 局号和结算时间；
- 结算前的庄家与老庄状态；
- 胡家或流局；
- 胡牌方式与倍率；
- 是否承包及承包者；
- 四人各自的分数变化和计算明细；
- 结算后的庄家与老庄状态。

用户可撤销最近一局。撤销必须同时恢复四人分数、庄家、连续坐庄局数与局号。只支持按时间逆序撤销，不支持任意修改中间历史。

## 5. 页面与视觉设计

### 5.1 页面结构

应用有两个主要页面状态：

1. 开场设置。
2. 牌局仪表盘。

发牌向导、结算向导和历史记录以局部抽屉或覆盖层呈现，不离开仪表盘上下文。

### 5.2 视觉语言

- 深青绿色表现麻将桌面。
- 象牙白牌面承载姓名、分数与操作信息。
- 朱红色仅用于“庄”标记、危险操作和最终确认。
- 中央圆角方桌是唯一的视觉焦点，四边玩家卡片对应真实物理座位。
- 结算时使用短暂的分数流动反馈；换庄时移动“庄”标记。
- 支持系统“减少动态效果”设置。
- 以手机竖屏和单手操作为设计基准，同时适配桌面宽屏。
- 交互控件具有清晰的键盘焦点与足够的颜色对比度。

## 6. 技术设计

项目为无后端的纯前端单页应用，使用原生 HTML、CSS 和 JavaScript，避免为单一工具引入框架和构建依赖。

代码按职责拆分：

- 规则与计分模块：牌型、庄闲倍率、承包和状态转移。
- 状态存储模块：当前牌局、本地持久化、历史和撤销。
- 座位与发牌模块：物理座位关系、骰子开门与发牌步骤。
- 界面模块：设置页、仪表盘、发牌向导、结算向导、历史抽屉和反馈消息。

整场状态保存在浏览器本地存储中。刷新或关闭页面后自动恢复。创建新牌局前必须二次确认，防止误清空。若存储数据无法解析或结构不合法，应用不继续计算，提示用户重新开局，并保留原始存储值供排查。

## 7. 质量验证

实现完成后进行以下验证：

### 7.1 核心计算测试

- 平庄、一老、二老下庄家与闲家胡牌。
- 所有胡牌方式倍率。
- 承包开启、关闭、庄家参与和纯闲家关系。
- 闲家胡后接庄、庄家胡后连庄、二老封顶。
- 流局不计分、不换庄、不增加连庄次数。
- 撤销完整恢复状态。

### 7.2 发牌规则测试

- 四个不同庄家位置。
- 两骰总点数 2 至 12。
- 开门牌墙、数墩方向、起牌点与取牌顺序。

### 7.3 浏览器交互测试

完整走通“设置座位 → 发牌 → 多局结算 → 换庄 → 刷新恢复 → 撤销”的流程。

检查手机竖屏与桌面宽屏，覆盖长姓名、负分、较大累计分、抽屉滚动、按钮可点区域、键盘焦点、颜色对比度和减少动态效果。最终检查关键页面截图，修复明显的布局和视觉问题。
