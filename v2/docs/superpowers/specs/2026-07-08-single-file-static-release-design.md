# 杭州麻将助手单文件静态发布设计

## 目标

在不破坏现有模块化源码与自动化测试的前提下，生成一个完全独立的 `dist/index.html`。用户只需将该文件复制到 Nginx 静态目录即可发布，不需要在服务器安装 Node.js、运行构建服务、配置数据库或部署其他组件。

## 交付结构

项目保留现有开发源码：

- `index.html`：开发页面结构。
- `styles.css`：页面视觉样式。
- `js/rules.js`、`js/dealing.js`、`js/state.js`、`js/app.js`：规则、状态、发牌和界面模块。
- `tests/`：核心规则与状态测试。

新增发布文件：

- `dist/index.html`：唯一需要发布的文件，包含完整 HTML、内嵌 CSS 和内嵌 JavaScript。

新增构建脚本只在开发或更新页面时运行。Nginx 服务器不运行该脚本，只负责返回已经生成的 HTML 文件。

## 单文件生成方式

构建脚本读取现有 HTML、CSS 和四个 JavaScript 模块，执行以下确定性转换：

1. 将 `styles.css` 内容写入 HTML 的 `<style>` 标签。
2. 移除 JavaScript 模块的 `import` 与 `export` 语法。
3. 按依赖顺序合并 `rules.js`、`dealing.js`、`state.js`、`app.js`。
4. 将合并结果写入普通 `<script>` 标签。
5. 输出 `dist/index.html`。

发布文件不包含对本地 JS、CSS、图片、字体、CDN 或网络接口的引用。页面加载后不发起外部请求。

## 运行与数据

- Nginx 只需将 `dist/index.html` 作为静态首页返回。
- 页面功能全部在浏览器运行。
- 四人座位、累计分、庄家、老数与历史记录继续保存在浏览器 `localStorage`。
- 同一 Nginx 域名和路径下刷新或关闭页面后可以恢复牌局。
- 直接双击 `dist/index.html` 也可运行；不同浏览器对 `file://` 下本地存储的隔离策略可能不同，因此持续记分以 Nginx 静态托管为主要使用方式。

## 手机端要求

单文件发布物必须保留现有移动优先设计，并满足以下明确标准：

- 主要适配 360px 至 430px 宽的手机竖屏，同时保持平板和桌面可用。
- 页面必须包含 `width=device-width` 与 `viewport-fit=cover`，适配刘海屏和底部安全区。
- 开局设置、桌面仪表盘、发牌向导、结算向导和历史记录均不得产生横向滚动。
- 方桌及四边玩家卡片必须在手机屏幕内完整可见；长姓名使用安全截断，不挤压分数和庄家标记。
- 所有主要按钮和选择控件的可点击高度至少为 44px，适合拇指操作。
- “结束本局”和“确认结算并开下一局”等关键操作在手机上保持清晰、可达，不被浏览器底栏或抽屉内容遮挡。
- 发牌与结算抽屉允许纵向滚动，底部确认区固定在抽屉内并考虑 `safe-area-inset-bottom`。
- 分数使用等宽数字显示，正负变化不能只依赖颜色区分。
- 支持 `prefers-reduced-motion`，减少动态效果时仍能清楚识别庄家变化和结算结果。

## 错误处理

- 构建时若缺少源码文件、找不到预期的 CSS 或模块脚本标签，立即失败，不生成不完整发布物。
- 构建前创建 `dist/`；已有 `dist/index.html` 可安全覆盖。
- 发布文件中的脚本不依赖模块加载，因此不会出现通过 `file://` 打开时的 ES Module 跨域限制。
- 浏览器本地数据异常时沿用现有应用提示，不静默计算或清空。

## 验证

1. 运行现有 65 项核心测试。
2. 运行构建脚本并确认生成 `dist/index.html`。
3. 检查发布文件中不存在 `src="js/`、`href="styles.css"`、`type="module"`、`import` 或 `export`。
4. 使用静态服务器仅托管 `dist/`，确认首页返回 200。
5. 确认发布目录中只有一个必需文件，且页面全部逻辑、样式均已内嵌。
6. 静态检查内嵌样式仍包含 430px 手机断点、安全区、44px 触控尺寸与减少动态效果规则。
7. 用户在手机浏览器中检查开局设置、桌面仪表盘、发牌、结算、历史和撤销流程。

实际浏览器视觉与交互测试由用户自行进行，与此前约定一致。
